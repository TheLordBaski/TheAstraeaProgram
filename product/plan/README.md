# The Astraea Program — release plan

This plan takes TAP from its vertical slice to a full release with the spaceflight content KSP had at its 1.0.

It adds TAP's own additions:
- transfer planning and an alarm clock;
- landmarks;
- multi-system foundations;
- planned expansions for more star systems and trade routes.

**What it contains:**
- 209 tasks in 18 workstreams;
- milestones from the first internal foundations to 1.0;
- estimates for a solo developer working with Claude;
- the decisions still open.

Written 2026-09-27, after the vertical slice (M0).

## Where we are: M0, the vertical slice (done)

The complete Luma mission is played and verified by automated missions in the Windows build: build → launch →
orbit → transfer → landing → EVA and flag → return → reentry → splashdown.

It sits on real systems:
- patched conics and manoeuvre nodes;
- per-part aerodynamics, heating and structural loads;
- docking and EVA;
- time warp without drift;
- an assembly building with symmetry, staging, set-aside parts and re-rooting;
- developer tools;
- a part-model pipeline that round-trips through Blender.

Evidence: [Docs/FEATURES_AND_LIMITATIONS.md](../../Docs/FEATURES_AND_LIMITATIONS.md).

## Schedule

**Two lanes:**
- **Claude**: Claude builds and tests while you steer and review.
- **You**: decisions, design, playtesting, and all the art and audio that is yours.

The lanes run largely in parallel: Claude works through a feature while you model parts. So the calendar is set by
the longer lane, plus a 15% buffer for integration and surprises.

The Claude estimates are **conservative**. The vertical slice was built several times faster than these numbers
would predict, but it was a greenfield sprint. Content, balance and integration work are slower. Two scenarios:

| Scenario | Claude lane | M1 + EA1 (first sale) | To 1.0 |
|---|---|---|---|
| **Plan pace**: estimates as written | 481 d | about 14 months full-time · 2.3 years at half-time | about 25 months full-time · 4 years half-time |
| **Slice pace**: Claude lane ~3× faster | ~160 d | about 7 months full-time · 14 months half-time | about 15 months full-time · 2.5 years half-time |

The **You** lane (281 days to 1.0) doesn't speed up with AI. At slice pace it becomes the bottleneck: art, audio
choices, playtesting and store work.

Ways to shorten:
- commission the characters and music (D-05, D-06);
- limit hand-made parts to the most visible;
- start the store page early so wishlists grow while you build.

**Recalibrate after M1**:
1. Compare actual days with the estimates per workstream.
2. Rescale.
3. Pick the EA1 date.

**If EA1 has to come sooner**, cut these to EA2:

| Cut | Saving |
|---|---|
| Rubra and Vigil (SYS-04, SYS-05 and their sky) | ~5 Claude and ~3 You days, but the launch loses its first planet |
| Tutorials 6–7 | about 2 days |
| Craft browser v2, body info panel, demo | about 5 days |

Everything else in EA1 is what a credible science-mode launch needs.

## Critical path

1. **Foundations first**: FND-15 → FND-01 → FND-03 → NAV-01 → NAV-02. Every world, the map and interplanetary play
   hang on the star-centred, multi-system core. FND-02 (terrain and biomes as data) unlocks every new world and all
   of science.
2. **Science loop for EA1**: FND-02 → SCI-01 → SCI-02 → SCI-03 → SCI-10 → TEC-02 → TEC-03 → balance (SCI-11,
   TEC-04).
3. **Hub**: FND-06 → FND-07 → HUB-02 → the R&D, tracking station and launch screens.
4. **Content**: PRT-01 → PRT-02 → PRT-12a → ASM-01.
5. **Proof**: FND-11 (CI, Linux) → QA-02 (autotests v2) → mission tests for every new feature → REL-06 releases.
6. **Career (EA3)**: FND-14 (events, objectives) → CAR-04 → CAR-05 → CAR-10.
7. **Your lane, start early because it is long**:
   - ART-01 → ART-02 → hero parts (ART-03a…e);
   - music and sound sourcing (D-06);
   - the store page and trailer (REL-04);
   - the name and trademark check (REL-02). Before any marketing.

## Main risks

| Risk | Mitigation |
|---|---|
| Scope vs one person's time | Every Early Access release is self-contained; cut lists; re-estimate after M1 and after each release; Early Access income and feedback shape the rest |
| Art is the long lane | 45 hand-made hero parts; improved procedural models for the rest (ART-04); commission characters (D-05) |
| Precision and "Kraken" bugs at solar distances | Star-centred frames and the precision suite early (FND-01, FLT-13); all nightly |
| Performance at 150–300 parts | Budgets in M1 (FND-13); per-part costs batched (FLT-14); single rigid body kept (D-14) |
| Science and career balance | Pacing simulations (SCI-11, CAR-10), playtests, optional telemetry (D-10) |
| Breaking players' saves during Early Access | Versioned migrations and a save corpus tested on every build (FND-05, QA-03) |
| Linux-only bugs | Linux in CI from M1; tested on real hardware every release |
| A name conflict after launch | Trademark search done: no conflict for the full name ([TRADEMARK_SEARCH.md](../TRADEMARK_SEARCH.md)). File the EU and US marks before the store page (D-23) |
| Engine upgrades mid-milestone | One Unity version per milestone; upgrade between milestones with a full test pass |
| Multi-system and trade creeping into 1.0 | Prepared in data now (FND-15) but built after 1.0 (X1, X2) unless you decide otherwise |

## Working with the plan

- **Pick work** by milestone. A task is ready when everything in *Needs* is done. Tick the *Done when* boxes as they
  pass; the automated ones must be in CI.
- **Change** the files freely: adding tasks, moving milestones, re-estimating. Then run `python
  product/plan/build_index.py` to rebuild `tasks.csv`, check every reference and print new totals.
- **Tracking**: `tasks.csv` imports into GitHub Projects or Issues (one issue per task, labels for milestone and
  workstream). I can create them for you.
- **Review** at each milestone end:
  - update estimates with actuals;
  - revisit the open decisions;
  - write the release notes from the finished tasks.
